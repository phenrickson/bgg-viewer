The landing page & a linked Explore workspace

A reaction mockup built on the app's real design tokens, continuing layout-ia-mockup.html. Two ideas to review: (1) a landing page that orients the user and quietly warms the game catalog in the background, and (2) an Explore canvas where the same set of games is shown as a plot and a table at once, linked — brush the plot, the table follows.

The idea it serves: a simple way to search and explore board games as a set — not one at a time.

Two levels, on purpose. The rail is the durable query (URL-carried, shareable) — it decides which games. The brush is a light, throwaway lens within the answer — drag a region of the plot and the table narrows to it; hover a row and its dot lights up. Clear the brush in one click; the query stays put.

Why linked, not tabbed

The client-side DuckDB catalog makes a brush re-query cost ~15ms — so the plot and table can move together for free. A toggle would under-use what's built.

Predictions live elsewhere

Per your call, the model gets its own /predictions room — Explore stays about querying the catalog, uncluttered by overlays.

The plot is the bridge

A scatter of the actual games is the games and their shape at once — which is why it, not the histograms, is the headline.
